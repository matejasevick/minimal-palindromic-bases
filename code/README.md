# Code and data for "Minimal palindromic bases of powers of two"

All programs are self-contained C (gcc, `-O3 -march=native`) or Python 3 (gmpy2, sympy, mpmath, numpy).
The Lean formalization is in `../lean/PalPow2`, and the output logs of the runs are in `../runs`.

| file | purpose |
|---|---|
| `core.py` | exact helpers: base-b digits, palindrome test, admissibility `binom_ok(n,x)`, `beta(n)`, brute-force `bmin(n)` |
| `betacalc.c` | tabulates β(n) for n ≤ 10^6 with extended-precision log-binomials, flagging comparisons within 1e-9 of a tie for exact recheck (`beta_1e6.txt`; the single tie n=6, x=2 is resolved there) |
| `minbase5.c` | exhaustive search (Section 10). `range N1 part nparts [plus1]`: every n ≤ N1 and every base 3 ≤ b < 2^β(n)−1 (with `plus1` the binomial base itself is included as a positive control), used for (C1). `single n Bmax part nparts`: one exponent, all bases < Bmax, used for (C2). `upto4 N1 part nparts root4.txt`: all bases with ≥ 5 digits, used for (C5) |
| `fixbase.c` | fixed-base scan: all n ≤ nmax with 2^n a palindrome in base b, for b in a range, used for (C3), (C4). Uses `alpha.txt` (128-bit values of log 2/log b), generated by `make_alpha.py` |
| `allpal60.c` | direct enumeration of all palindromic representations of 2^n with ≥ 3 digits for n ≤ 60, used for (C5) and Remark 5.6 |
| `three.py` | non-binomial (1,c,1)_b representations via cyclotomic factorisation of 2^n − 1 (Section 8) |
| `nearpal.py` | near-palindromes: longest run of matching outer digit pairs (exploratory, not used in the paper) |
| `heuristic.py` | random-digit model: expected number of counterexamples to b(2^n) = 2^β(n) − 1 (Section 12) |
| `beta.txt`, `beta_1e6.txt.gz` | β(n) for n ≤ 1500 (exact integer arithmetic) and n ≤ 10^6 (gunzip before use) |
| `root4.txt` | floor(2^(n/4)) for n ≤ 250, input for `upto4` mode |
| `allpal_60.txt` | output of the n ≤ 60 enumeration (6 ≤ n ≤ 60; the only case with n < 6 is 2^4 = (1,2,1)_3) |

Build and run examples:

```
gcc -O3 -march=native -mprefer-vector-width=512 -o minbase5 minbase5.c -lm
./minbase5 range 1000 0 2 plus1 &  ./minbase5 range 1000 1 2 plus1      # (C1): ~1.2 h on 2 cores
./minbase5 single 1521 549755813887 0 2 & ./minbase5 single 1521 549755813887 1 2   # (C2), a = 39
./minbase5 single 400 1048576 0 1          # positive control for single mode: finds only b = 2^20 - 1
./minbase5 single 784 268435456 0 2 & ./minbase5 single 784 268435456 1 2   # positive control: finds only b = 2^28 - 1
./minbase5 upto4 140 0 2 root4.txt & ./minbase5 upto4 140 1 2 root4.txt   # (C5), >= 5 digits, n <= 140
gcc -O3 -march=native -o fixbase fixbase.c -lm
./fixbase 3 3 10000000000 alpha.txt        # (C3)
./fixbase 3 1000 1000000 alpha.txt         # (C4), bases <= 1000
./fixbase 1001 65535 100000 alpha.txt      # (C4), 1000 < b < 2^16
gcc -O3 -o allpal60 allpal60.c && ./allpal60 1 60   # (C5), n <= 60
python3 heuristic.py; python3 nearpal.py 20000
```

With `plus1`, the expected output is exactly one `PAL` line per n, at b = 2^β(n) − 1.
Any other `PAL` line would be a counterexample to b(2^n) = 2^β(n) − 1.
